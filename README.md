# api

API definitions for bpmf products. Contracts are maintained Protocol
Buffers-first: this repository contains definitions only, implementations
live in the service repositories. It is also a Go module (`bpmf.io/api`)
that ships the generated Go code, so Go services consume the contracts
with `go get`.

## Layout

| Path | API |
| --- | --- |
| `bpmf/lead/v1` | `LeadService.SubmitLead` — public sales-lead collection, the entry point of the sales funnel MVP |

Conventions: the package `bpmf.<domain>.v1` mirrors the file directory, and
`go_package` mirrors the directory under this repository's module path
(`bpmf.io/api`). Go code is generated by `buf generate` (see `buf.gen.yaml`)
and committed next to the protos: run `make generate` after every proto
change. Run `buf dep update` after adding a dependency in `buf.yaml`, and
commit the generated `buf.lock` together with it.

## Checks

Install [buf](https://buf.build), then:

```sh
make build     # buf build: resolve deps and compile all protos
make generate  # buf generate: refresh the committed Go code
make lint      # buf lint: STANDARD rule set, zero warnings expected
make format    # buf format -w: canonical formatting
make breaking  # buf breaking --against '.git#branch=main'
make check     # build + lint + format check in one go
```

CI (GitHub Actions) runs build, lint, and format checks on pushes and pull
requests, and breaking-change detection against the PR base. It also verifies
that the committed Go code is up to date (`buf generate` leaves the tree
clean) and that it builds. To land an intentional breaking change, add the
`buf skip breaking` label to the PR.

## Consuming

### Go

The generated Go code is committed to this repository, so Go services can
import the contracts directly:

```sh
go get bpmf.io/api/bpmf/lead/v1
```

```go
import leadv1 "bpmf.io/api/bpmf/lead/v1"
```

`bpmf.io/api` is a vanity module path: it resolves through the `go-import`
meta tag that must be served with status 200 at
`https://bpmf.io/api?go-get=1`:

```html
<meta name="go-import" content="bpmf.io/api git https://github.com/bpmfio/api">
```

Until that meta tag is live, consume the repository through a `replace`
directive instead:

```sh
# From a local checkout:
go mod edit -replace=bpmf.io/api=../api
# From the GitHub repository, pinned to a released tag:
go mod edit -replace=bpmf.io/api=github.com/bpmfio/api@v0.1.0
```

Tag releases as `vX.Y.Z` so `go get` and `replace` can pin versions.

### Other languages

Code for other languages can be generated by pointing `buf generate` at this
repository using your own `buf.gen.yaml` template:

```sh
git clone https://github.com/bpmfio/api.git
cd api
buf dep update
buf generate --template <path-to-your>/buf.gen.yaml
```

With protoc, put this repository, [googleapis](https://github.com/googleapis/googleapis),
and the protobuf well-known types on the include path:

```sh
protoc -I . -I <path-to-googleapis> --go_out=out bpmf/lead/v1/lead.proto
```

## Adding a new API

Create `bpmf/<domain>/v1/<domain>.proto` with package `bpmf.<domain>.v1`,
document every message, field, enum, and RPC (lint enforces comments), run
`make generate` to refresh the committed Go code, and run `make check` before
committing.
